# Reusable task and feedback briefs

These headings work in Word, OneNote or Loop. Link a brief from its feature roadmap rather than keeping contradictory copies of a specification.

Read the linked master specifications first. Inspect existing code before proposing changes. Implement one bounded task at a time. Preserve raw CSS, original art, saved owner settings and external-goal authority. Report what changed, evidence, remaining limitations and owner acceptance separately. Update the affected roadmap and handoff. Do not broaden into unrequested redesign.

## Art review brief

Use the approved reference and ART_RULES.md. Describe the camera, proportions, pixel scale, palette, material boundaries, depth, light source, masks and animation timing before rendering. Identify existing source pixels to preserve. Review at native and enlarged scales. Mark experiments as drafts until owner approval.

## Working mode

Plan first for architectural, ambiguous or multi-feature changes. Implement/debug one well-defined card in the normal editing workflow. Use image generation for new bitmap art; use source/code edits for existing masks, geometry and rendering behavior. Every model gets the same locked brief and references. Model output is not approval.
